# Codex Maestro

Codex의 프로젝트와 세션을 한 화면에서 보고, 연결하고, 다음 작업을 지시하는 macOS 네이티브 앱입니다.

SwiftUI / AppKit · macOS 26 이상 · Swift 6 · 외부 패키지 의존성 없음

## 실행

`make install`은 Release 앱을 빌드하고 `/Applications/Codex Maestro.app`에 설치합니다. Codex 데스크톱을 실행한 상태에서 설치한 앱을 여세요.

```sh
make install
open "/Applications/Codex Maestro.app"
```

설치 스크립트는 [scripts/install-app.sh](scripts/install-app.sh)입니다. 다른 설치 폴더는 `./scripts/install-app.sh "$HOME/Applications"`처럼 지정할 수 있습니다. 스크립트는 대상 볼륨에 복사본을 만들고 서명을 검증한 뒤 설치합니다. 기존 대상의 번들 ID가 다르거나 설치된 앱이 실행 중이면 중단합니다. 기존 설치는 백업 없이 교체하며 사용자 작업공간은 별도 위치에 유지합니다. 쓰기 권한이 없는 폴더에서는 오류를 표시합니다. 패키징만 필요한 경우 `make app`은 `dist/Codex Maestro.app`을 생성합니다.

Xcode 개발 진입점은 [CodexMaestro.xcodeproj](CodexMaestro.xcodeproj)입니다. 앱, `MaestroCore` 정적 라이브러리, `MaestroProbe`, Core·앱 XCTest의 5개 타깃이 같은 소스를 사용합니다. 최소 배포 버전은 `26.0`, Swift 언어 모드는 `6.0`입니다.

공유 scheme은 `CodexMaestro`(일반 실행·두 테스트 타깃·Release archive), `CodexMaestro Demo`(격리된 데모 실행), `MaestroProbe`(읽기 전용 연동 진단)입니다. 일반 실행은 실제 로컬 Codex에 연결합니다. `CodexMaestro`의 테스트 호스트는 `--demo`로 실행하므로 실제 작업공간을 읽거나 저장하지 않습니다.

프로젝트 원본 설정은 [project.yml](project.yml)입니다. 생성된 프로젝트가 저장소에 포함되어 있으므로 일반 Xcode 개발에는 XcodeGen이 필요하지 않습니다. 타깃·파일 구성을 바꿔 재생성할 때는 XcodeGen 2.46.0 이상을 사용합니다. 앱 아이콘은 기존 생성기에서 만든 asset catalog를 포함하며 `scripts/generate-icon-assets.sh`로 다시 생성할 수 있습니다.

```sh
make xcode-build    # 네이티브 Xcode Debug 빌드
make xcode-test     # 네이티브 Xcode XCTest
make xcode-project # project.yml에서 프로젝트 재생성
```

SwiftPM 개발도 유지합니다. `Package.swift`는 Swift tools 6.2 이상, macOS 26, Swift 6 언어 모드를 지정합니다.

```sh
make run      # 실제 로컬 Codex에 연결
make demo     # 격리된 데모 데이터, 실제 전송 및 저장 없음
make test     # 단위 및 Unix 소켓 통합 테스트
make probe    # 읽기 전용 실제 연결 진단
make app      # release 빌드 + .app 생성 + 로컬 ad-hoc 서명
make install  # release 빌드 + /Applications에 설치
```

`make app`에는 Xcode/Command Line Tools의 Swift, sips, iconutil, codesign이 필요합니다. 앱 실행 자체에는 Node.js나 Python이 필요하지 않습니다. `dist`의 SwiftPM 앱은 Apple Silicon용이며 Xcode Release archive는 arm64·x86_64를 포함합니다. 실제 실행은 Apple Silicon의 macOS 27에서 확인했습니다. macOS 26과 Intel의 실행은 별도 검증이 필요합니다. 두 빌드 경로는 로컬 ad-hoc 서명을 사용합니다. 배포용 Developer ID 서명 및 공증은 포함하지 않습니다.

Xcode 앱의 App Sandbox는 기존 로컬 DB·Unix 소켓 접근 계약에 따라 비활성화합니다. User Script Sandboxing은 활성화합니다. `MaestroCore`는 Swift 소비자만 있으므로 Objective-C 인터페이스 헤더를 설치하지 않습니다. `MaestroProbe`의 `main.swift`는 `@main`을 사용하므로 해당 타깃에 `-parse-as-library`를 지정합니다.

## 주요 기능

- 사용자 정의 판단. Choice·Score·Noul, 의존 단계·분기·본문 조회, 가중치·필수 조건을 Profile로 구성합니다. 요청·응답 원본을 확인하고 저장·복제·가져오기·내보내기할 수 있습니다. [공통 판단 계층과 Profile 예제](docs/DECISIONS.md)에 계약과 사용 범위를 설명합니다.
- 세션 상세 작업 회로. 선택한 요청의 프롬프트·지침·호출·결과·하위 세션·공개 메시지·토큰을 연결합니다. 상태 관찰 원문, 과거 이벤트 재생, 호출·하위 회로와 확인 범위를 제공합니다. [작업 회로의 기록·상태·토큰 계약](docs/SESSION-WORK-CIRCUIT.md)에 범위와 한계를 설명합니다.
- 프로젝트별 작업 흐름. 세션 제목과 실시간 상태를 표시하며, 저장 기록은 현재 상태와 구분합니다.
- 세션 카드와 목록에 마지막 저장된 사용자·Codex 텍스트 메시지를 표시합니다. 작성자를 함께 표시하고, 공백을 정리한 최대 160자를 두 줄로 제한합니다. 긴 문장은 말줄임표로 자릅니다.
- macOS 기본 툴바, 밝은·어두운·시스템 화면 모드, 사이드바와 상세 패널 표시 전환.
- 파란 선택 표시, 프로젝트 소속선, 목적과 방향을 표시한 연결선, 연결선 범례.
- 프로젝트와 세션 노드 선택 시 들어오는·나가는 모든 유형의 관계 표시.
- 최근 작업, 데스크톱에서 연결된 세션, 전체 로컬 세션, 프로젝트별 필터와 검색.
- 프로젝트와 세션 아이템 드래그, 확대/축소, 스크롤, 배치 초기화, 연결선 숨기기, 세션 목록 보기.
- 선택한 세션의 최근 대화와 요청 입력. 모델·추론·경로·브랜치·ID는 `정보`를 펼쳐 확인합니다.
- 세션별 프롬프트 초안과 전송. 기존 모델·추론·권한을 유지합니다. 단축키는 `⌘Return`입니다.
- 컨텍스트 전달 / 선행 작업 / 검토 요청의 방향 있는 세션→세션, 프로젝트→프로젝트, 세션→프로젝트, 프로젝트→세션 연결.
- 아이템을 다른 아이템에 겹쳐 놓으면 참고 / 전달 / 검토 / 직접 요청 중 다음 작업을 선택합니다. 취소하면 연결과 위치를 바꾸지 않습니다.
- 세션을 두 번 클릭하면 작업 회로를 엽니다. `기록 지도`에서 기존 전체 컨텍스트 지도로 전환할 수 있습니다. 프로젝트를 두 번 클릭하면 기존 프로젝트 기록 지도를 엽니다.
- 컨텍스트 / 툴 최적화 요청을 편집하고 실제 담당 세션의 초안으로 준비합니다. 프로젝트의 담당 세션은 사용자가 지정합니다.
- 통합 연결 관리자에서 연결 생성·편집·삭제, 서로 다른 프로젝트의 세션 연결 및 현재 목록에 없는 연결 대상 수정.
- 각 연결에서 작업할 쪽과 참고할 쪽을 구분하고, 실제 실행 세션의 초안을 미리 확인한 뒤 준비합니다. 스킬은 해당 세션이 요청에 맞게 선택합니다.
- Codex에서 원래 세션 열기, 프로젝트를 Finder에서 열기, 작업 흐름 JSON 내보내기.
- 작업공간 저장과 연결 복구. 전송 실패 시 초안을 유지하고, 결과가 불확실한 요청을 자동 재전송하지 않습니다.

프로젝트 또는 세션 **아이템 자체를 다른 아이템에 겹쳐 놓으면** `다음 작업` 창을 엽니다. 참고 / 전달 / 검토 / 직접 요청 중 하나를 선택할 때 방향 있는 연결과 기능 설정을 저장하고 요청 창으로 이동합니다. 선택 전에 취소하면 연결·위치·초안을 바꾸지 않습니다. 빈 곳에 놓으면 위치만 저장합니다. 연결 아이콘을 누른 뒤 대상을 클릭하는 대체 경로와 연결 관리자도 사용할 수 있습니다. 저장한 연결의 요청 창을 닫아도 연결은 유지하며, 관리자나 상세 패널의 `요청`에서 다시 열 수 있습니다.

`참고`는 기본적으로 출발 쪽에서 도착 쪽 자료를 참고합니다. `전달`과 `검토`는 기본적으로 도착 쪽에서 출발 쪽 자료를 이어받거나 검토합니다. `직접 요청`은 출발 쪽을 기본값으로 직접 요청을 작성합니다. 네 기능 모두 `담당`에서 어느 쪽이든 선택할 수 있으며, 반대쪽이 `참고`에 표시됩니다. 연결선의 방향 자체가 실행 위치를 강제하지는 않습니다.

작업할 항목이 세션이면 그 세션이 실제 실행 대상입니다. 프로젝트이면 현재 그 프로젝트에 속한 세션을 사용자가 명시적으로 선택해야 합니다. Maestro에서 스킬을 고르는 메뉴는 없습니다. 준비하는 프롬프트가 실제 실행 세션에 요청에 적합한 사용 가능한 스킬을 선택하도록 지시하며, 적합한 스킬이 없으면 일반 작업 방식으로 진행하도록 안내합니다.

`보낼 내용`을 펼치면 실제 생성한 초안을 확인할 수 있습니다. `초안 준비`는 이 미리보기와 같은 내용을 실제 실행 세션의 초안으로 옮깁니다. 기존 초안이 있으면 덮어쓰거나 자동으로 덧붙이지 않고 멈춥니다. 실제 작업은 그 세션에서 초안을 검토하고 **전송**할 때 시작합니다. 연결이나 기능 설정 저장은 메시지를 전송하거나 세션 소속을 변경하지 않습니다. 연결의 모든 요청은 같은 준비 흐름을 사용합니다. 초안을 준비한 뒤에도 다른 프로젝트를 계속 표시합니다. 현재 동작과 기록 범위는 [컨텍스트 토폴로지와 아이템 겹치기](docs/CONTEXT-TOPOLOGY.md)에 기록합니다.

전체 작업 흐름 목록에는 보관되지 않은 **로컬 Codex 세션**이 포함됩니다. 프로젝트나 세션 카드, 사이드바 프로젝트, 세션 목록 항목을 두 번 클릭하면 컨텍스트 화면으로 전환합니다. 프로젝트 컨텍스트에는 보관된 구성원 세션도 포함합니다. 하위 기록과 관찰된 툴을 펼치고, 선택한 기록의 전체 본문을 필요할 때 읽습니다. 이 지도는 저장된 기록을 보여주며 현재 모델에 실제 전달된 입력 전체나 현재 사용 가능한 툴 목록을 증명하지 않습니다. 화면의 범례와 조작 설명은 정보 버튼에 접었습니다.

기본 `최근 작업`은 최근 40개와 실시간 연결 세션을 표시하며, 프로젝트 카드는 3개의 최근 세션 및 실시간 세션을 먼저 보여줍니다. `전체 세션`은 전체 카탈로그를 선택합니다. 각 프로젝트의 카드는 기본적으로 접혀 있습니다. `더 보기` 또는 사이드바의 프로젝트 선택으로 해당 프로젝트의 모든 카드를 펼칠 수 있습니다. 캔버스의 프로젝트 노드 선택은 그래프 필터를 유지하면서 프로젝트 상세만 표시합니다. 제목이 없는 내부 세션은 `제목 없는 세션`으로 표시됩니다.

## 연동 방식과 범위

1. `~/.codex/state_*.sqlite`에서 프로젝트와 세션 메타데이터를 읽기 전용으로 조회합니다. `CODEX_HOME` 환경 변수를 지정하면 해당 경로를 사용합니다.
2. `~/.codex/thread_history_1.sqlite`에서 최근 저장된 텍스트 메시지 최대 30개를 상세 패널에 표시합니다. 세션 아이템은 같은 DB의 기록 순서를 역순으로 조회해 마지막 사용자·Codex 텍스트를 표시합니다. DB에 텍스트가 없는 이전 세션은 원본 rollout 파일의 끝에서 역순으로 읽습니다. 도구 기록, 빈 메시지, 이미지뿐인 메시지와 내부 reasoning은 건너뜁니다. 두 출처 모두 읽을 수 없으면 아이템에 `대화 미리보기 없음`을 표시합니다. 상세 패널의 레거시 미리보기는 기존 초기 요청을 유지합니다. 메타데이터와 저장된 대화는 5초 간격으로 갱신합니다.
3. `~/.codex/ipc/ipc.sock`을 통해 Codex 데스크톱의 상태 스트림을 구독합니다. 수신한 스냅샷 및 연속된 revision의 패치로 실행 상태를 갱신합니다. 패치 순서가 어긋나면 재스냅샷을 요청합니다.
4. 컨텍스트 화면은 범위에 해당하는 rollout JSONL 기록을 읽고, 기록이 없거나 불완전하면 저장된 thread history를 대체 자료로 읽습니다. 프로젝트의 보관된 구성원, 현재 디스크의 AGENTS 지침, 확인 시점의 Maestro 연결·요청 설정을 함께 표시하며 각 출처의 확인 범위를 구분합니다.
5. 프롬프트 전송 시 소유자 탐색 후 해당 클라이언트에 `thread-follower-start-turn`을 한 번 전달합니다. 열리지 않은 세션은 Codex에서 먼저 열어야 합니다. 별도 app-server로 기존 세션을 resume하지 않습니다.

**현재 연동은 공개 지원 SDK가 아닌 Codex 데스크톱의 내부 IPC와 로컬 DB 어댑터입니다.** 실제 확인 환경은 데스크톱 `26.930.31428 (12913)`, 번들 CLI `0.160.0`입니다. 이후 업데이트에서 스키마 또는 프로토콜이 바뀌면 어댑터 수정이 필요할 수 있습니다. 내부 소켓에 연결된 앱은 세션 내용을 관찰할 수 있으므로, 이 앱은 로컬 사용자 계정에서 실행하는 신뢰된 개발 도구로 설계했습니다.

현재 지원 범위는 이 Mac의 로컬 Codex 프로젝트 및 세션입니다. ChatGPT 클라우드 대화, 원격 호스트 목록, 클라우드 프로젝트 동기화, 자동 다중 세션 실행, 승인 요청에 대한 대리 응답은 구현하지 않았습니다. Codex의 승인·사용자 입력 요청은 원래 Codex 창에서 처리합니다.

## 데이터 저장

Maestro의 관계·배치·초안을 저장하는 파일은 아래와 같습니다.

```text
~/Library/Application Support/CodexMaestro/workspace.json
```

화면 모드는 앱의 UserDefaults에 저장합니다. 모든 유형의 연결, 연결별 기능·실행 위치·받는 세션·요청, 노드 위치, 세션별 초안을 원자적으로 저장하고 파일 권한은 `0600`으로 설정합니다. Codex DB, 설정, 인증 파일, 세션 기록을 직접 수정하지 않습니다. 인증 토큰을 읽거나 복제하지 않습니다. 전송은 Codex의 기존 데스크톱 프로세스가 처리합니다. 내보내기 JSON에는 세션별 프롬프트 초안을 포함하지 않습니다. 연결 기능 설정에는 직접 작성한 요청이 포함될 수 있습니다.

연결 기능 설정이 있는 작업공간은 schema 3으로 저장하며, 이전 schema 1·2도 읽습니다. 예전 `.skill` 설정은 직접 요청 기능으로 정규화하고 원래 요청·실행 위치·받는 세션을 유지합니다. 수동 스킬 이름과 경로는 저장 시 제거합니다.

저장 파일이 손상됐거나 지원하지 않는 버전이면 해당 실행 중 저장을 중단하고 오류를 표시합니다. 원본 파일을 빈 작업공간으로 덮어쓰지 않습니다. 데모 모드는 실제 작업공간을 읽거나 쓰지 않습니다.

## 검증

공통 판단 계층의 API 경계 검사를 반영한 소스에서 Xcode와 SwiftPM의 **176개 테스트**가 각각 통과했습니다. Core 94개와 앱 82개입니다. 기존 세션 미리보기·원본 파일 불변 검사를 유지하고, Noul 정의 조건, Score 1–10단계, 정규화 제한, 필드 경로와 HTTP 오류 원본 보존을 검사했습니다.

등록된 TypeSafe 키로 합성 입력 32건을 실제 API에 전송했습니다. 19건은 성공했고 잘못된 형식의 13건은 HTTP 400·422로 거부됐습니다. 현재 코드로 저장된 요청·응답을 네트워크 없이 다시 검사한 결과 32건 모두 일치했습니다. Release 패키지와 strict 서명을 확인했습니다. 설치 상태와 native 판단 화면의 미검증 범위는 [검증 기록](docs/VALIDATION.md)에 구분했습니다. 이 검증은 한국어 업무 자료의 판단 품질이나 임계값을 검증하지 않습니다.

이전 macOS 26·Swift 6 전환에서는 Xcode Release archive와 로컬 서명을 검증했습니다. Swift 6의 actor 경계에 맞게 IPC 응답 continuation은 `Data`를 전달하고 수신 메시지 묶음은 `sending`으로 이전합니다. 잘못된 프레임이 포함된 묶음 전체를 거부하는 회귀 검사를 유지합니다.

전환 후 읽기 전용 Probe는 프로젝트 31개, 로컬 세션 608개, live snapshot 13개와 최근 대화 30개를 확인했습니다. 수량은 확인 시점의 값입니다. 이전 단순화의 변경량과 UI 확인 범위는 [단순화 적용 기록](docs/CLEANUP.md)에 있습니다.

실제 데이터 조회, 데스크톱 상태 수신, 앱 실행과 주요 UI 동작을 확인했습니다. 프롬프트의 대상 및 wire payload는 격리된 Unix 소켓 테스트 서버에서 검증했습니다. 기존 실제 업무 세션에 검증용 프롬프트를 보내지는 않았으므로, 실제 모델의 응답 완료까지 포함한 전송 E2E는 미검증입니다.

## 전체 세션 화면의 드래그 성능

드래그 좌표는 개별 카드의 `GestureState`에 저장합니다. 움직이는 카드의 연결선은 별도 상태를 관찰합니다. 전체 토폴로지의 배치와 정지한 연결선은 드래그 좌표 갱신에 의존하지 않습니다. 빈 곳에 놓은 노드 위치만 드롭 시 저장합니다. 다른 아이템에 겹쳐 놓으면 원래 위치를 유지하고 다음 작업을 묻습니다. 배경 점은 밝은·어두운 테마별로 캐시한 18pt 이미지 타일을 반복하여 표시합니다.

성능 검증용 실행 모드는 작업공간 파일을 저장하거나 Codex에 프롬프트를 보내지 않습니다.

```sh
MAESTRO_PERFORMANCE_LOG=1 "$(swift build -c release --show-bin-path)/CodexMaestro" --performance-demo
MAESTRO_PERFORMANCE_LOG=1 "$(swift build -c release --show-bin-path)/CodexMaestro" --performance-catalog
```

`--performance-demo`는 601개 합성 세션을 펼칩니다. `--performance-catalog`는 현재 로컬 카탈로그의 모든 세션을 읽기 전용 스냅샷으로 펼칩니다. 실제 Codex 실시간 연동은 일반 실행 모드에서 검증합니다.
