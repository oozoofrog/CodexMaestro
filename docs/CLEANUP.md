# 단순화 적용과 검증

적용일: 2026-10-03 (Asia/Seoul)

승인한 단순화를 적용했다. Swift 소스는 **146줄**, 테스트는 **37줄** 줄었다. 순감소는 **183줄**이다. 적용 전후 파일별 물리적 줄 수와 SHA-256은 `evidence/cleanup-line-counts.json`에 기록했다. 문서와 생성 산출물은 제외한다. 초기 감사의 246줄 추정은 최종 결과로 사용하지 않는다.

## 적용 범위

- 도달할 수 없는 `LinkEditor`와 전용 sheet·선택 상태를 제거했다. 연결 아이콘은 `LinkEndpoint`를 받는 기존 경로를 사용한다.
- 이전 `prepareHandoff`를 제거했다. 전달 테스트는 저장된 정확한 `NodeLink`와 `.handoff` / `.target` 설정으로 `prepareConnectionAction`을 호출한다. 기존 초안 충돌, 전체 프로젝트 유지, 실패 복구와 무전송 조건을 검사한다.
- 앱 저장소의 단순 연결 생성·삭제 어댑터와 이웃 조회 어댑터를 제거했다. 호출자는 typed 연결 API와 `incidentLinks`를 사용한다.
- 연결 라벨과 실행 대상을 `ConnectionFunction.label`과 `configuration.executionEndpoint(for:)`에서 직접 읽는다. 사용하지 않는 요약과 성능 fixture 생성기를 제거했다.
- `ProjectInspectorSummary`는 `nodeLinks`를 필수 입력으로 받는다. 이전 연결 배열과 선택적 fallback을 제거했다.
- 드래그의 사용하지 않는 점 기반 대상 판정, 인수, 캐시와 항상 참인 분기를 제거했다. 시작 상태 고정, 위치 드래그, 취소, 대상 표시와 아이템 겹치기 경로는 유지했다.

`Models.swift`의 기존 저장 형식 호환과 연결 유형 검사는 유지했다. `Models.swift`, `ContextTopologyLoader.swift`, `DesktopBridge.swift`는 이전 검증 manifest와 바이트 단위로 같다. `DraggableSessionNode` 인라인화와 지침 탐색 통합은 이번 적용에서 제외했다.

## 자동 검증과 변경 후 검토

| 검증 | 결과 | 근거 |
|---|---|---|
| 전체 XCTest | Core 45개 + 앱 73개, **118개 통과**, 실패 0개 | `evidence/cleanup-tests.log` |
| Release 빌드·패키징 | 통과 | `evidence/cleanup-package.log` |
| strict ad-hoc 서명 | 종료값 0 | `evidence/cleanup-artifact.json` |
| 현재 소스·검증 입력 | manifest 50개 파일의 SHA-256 일치 | `evidence/cleanup-artifact.json` |
| 변경량 | 18개 파일의 현재 줄 수·SHA-256과 합계 일치 | `evidence/cleanup-line-counts.json` |

이전 123개에서 빠진 5개는 삭제한 점 기반 판정 테스트 4개와 typed 연결 검사에 합친 이웃 어댑터 테스트 1개다. 중복 관계와 선택 없는 상태의 검사는 typed 검사에 유지했다. 실제 `TopologyDragState.offset` 갱신을 관찰하는 성능 회귀 검사도 유지했다. 이 검사는 FPS를 측정하지 않는다.

저장 실패 fixture는 연결을 먼저 저장한 뒤 저장 디렉터리의 상위 경로를 파일로 막는다. 받는 세션의 초안은 비워 두고 준비한 프롬프트를 제공한다. 따라서 초안 충돌에서 먼저 중단하지 않는다. 테스트는 **“작업공간 저장 실패”** 오류를 요구한다. 직렬화한 작업공간 전체, 선택, 표시 범위, 검색, 안내, 이벤트 수와 상위 경로 파일 내용이 바뀌지 않는지 검사한다.

최종 바이너리 SHA-256은 `acedb9d03a2d23220693507d5db7b91fe47a1ac5c867758cd4b927d5d5b9f0a9`다. manifest SHA-256은 `8b72f49a6cfb849abdd42e57f87fd6d47b1bc5371dd9c1f476d9dfadb6b363e2`다. 별도 팀원이 현재 50개 파일, 바이너리, 변경량 기록 18개 파일과 합계를 다시 계산해 일치를 확인했다. 변경 전 줄 수와 해시는 통합 담당자가 적용 전에 기록한 값이며 현재 파일만으로 다시 구성할 수 없다.

Astra는 통합 담당자와 다른 팀원의 저장소·연결창·테스트 이전을 읽기 전용으로 검토했다. typed 연결의 네 방향 조합, 유효하지 않은 대상, 기존 관계 ID 재사용, 전달 초안 충돌, 저장 실패 복구와 무전송 단언을 확인했다. 이 범위에서 차단 결함은 발견하지 않았다. Astra가 직접 수정한 토폴로지 파일은 독립 검토 범위와 구분한다. 토폴로지 변경은 통합 담당자의 소스 확인, 전체 회귀 테스트와 아래 네이티브 UI 확인에 포함한다. Astra 검토에는 직접 UI 조작이나 실제 IPC 전송이 포함되지 않는다.

## 최종 패키지의 네이티브 확인

통합 담당자는 최종 Release 앱의 데모에서 다음을 직접 확인했다. 데모의 연결과 초안 변경은 메모리에만 남는다.

- 프로젝트 더블 클릭으로 3개 세션·33개 항목의 컨텍스트 지도를 열었다.
- DESIGN을 MODELS에 일반 드래그로 겹쳤다. 참고·전달·검토·직접 요청과 취소를 표시했다. 취소하면 원래 보드로 돌아왔다.
- DESIGN의 연결 아이콘을 누르고 WATCH를 선택했다. 공통 요청창이 열렸고 네 작업 라벨과 출발·도착 담당을 표시했다.
- 전달을 선택하면 도착 쪽 WATCH가 담당이 됐다. 편집한 요청을 준비하면 WATCH의 편집기에 출처와 참고 자료를 포함한 프롬프트가 나타났다. 세 프로젝트를 계속 표시했다. 전송 버튼은 누르지 않았다.

근거는 `evidence/cleanup-ui-ax.log`와 `evidence/cleanup-handoff-prepared.png`다. 화면은 초안 준비 후 상태를 보여준다. 취소의 전체 작업공간 보존과 실패 복구는 별도 회귀 검사에서 확인한다.

일반 모드로 다시 열고 실제 CodexMaestro 프로젝트를 두 번 클릭했다. 9개 세션·14,290개 항목의 지도를 표시했다. 전체 카탈로그는 607개 세션, 열린 세션은 11개였으며 footer는 `Codex 연결`과 실행 2개를 표시했다. 수량은 확인 시점의 값이다. `evidence/cleanup-normal-ui-ax.log`에 기록했다. 최초 실행 화면의 열린 세션은 0개였고 이후 조회에서 11개로 바뀌었다. 최초 0개는 직접 관찰 기록이며 저장한 일반 UI 로그는 이후 11개 상태를 보여준다. 상태 수신 지연의 원인은 이번 변경에서 확인하거나 수정하지 않았다.

실제 업무 세션에 검증용 연결·요청을 만들거나 프롬프트를 전송하지 않았다. 일반 앱의 기존 자동 저장은 수행될 수 있으므로 이 실행 전체를 파일 변경이 없는 조회로 주장하지 않는다. 실제 모델 응답 완료, 실제 스킬 호출, 새 FPS 측정, 임의 대형 자료의 응답성, Intel 실행, 전체 VoiceOver 탐색, 공증과 외부 배포는 이번 검증에 포함하지 않는다.
