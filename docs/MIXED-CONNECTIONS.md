# 프로젝트·세션 혼합 연결

검증일: 2026-10-03 (Asia/Seoul).

이 문서는 Command 드래그 작업 설정을 추가하기 전의 71개 테스트 및 실행 기록이다. 현재 앱은 프로젝트가 포함된 연결에서도 담당 세션을 명시하여 초안을 준비하며 작업공간 버전 1부터 3까지 읽는다. 최신 동작은 [COMMAND-CONNECTIONS.md](COMMAND-CONNECTIONS.md), 최신 검증은 [VALIDATION.md](VALIDATION.md)에 기록한다.

## 구현한 동작

연결 관리와 캔버스에서 세션→세션, 프로젝트→프로젝트, 세션→프로젝트, 프로젝트→세션을 생성한다. 출발과 도착은 각각 노드 유형과 ID로 식별한다. 같은 문자열 ID를 사용하는 프로젝트와 세션도 서로 다른 노드다. 방향, 연결 목적, 메모를 저장하고 양쪽 상세 패널에 받은 연결과 보낸 연결을 표시한다.

연결 편집기에서 출발·도착의 유형과 대상을 각각 변경할 수 있다. 유형을 바꿔도 UUID와 메모를 유지한다. 같은 저장 배열 안에서 편집하면 순서도 유지한다. 자기 연결과 같은 방향·목적의 중복을 거부한다. 현재 목록에서 사라진 대상은 저장 목록에 남으며, 수정과 삭제가 가능하다. 새 연결과 수정은 실제 대상의 존재를 확인한다.

캔버스의 프로젝트와 세션 카드에 연결 버튼을 제공한다. 프로젝트 없는 세션 묶음은 합성 그룹이며 실제 프로젝트 연결 대상으로 취급하지 않는다. 세션이 없는 등록된 프로젝트는 연결 대상으로 사용할 수 있다. 프로젝트 필터는 표시 범위를 제한하고, 캔버스의 노드 선택은 상세를 바꾼다.

프로젝트가 포함된 연결은 참고 관계를 저장한다. 연결 생성은 세션 소속을 바꾸거나 메시지를 보내지 않는다. 세션→세션에만 기존 전달 초안 기능을 제공한다. 프로젝트 수신함, 담당 세션 선택, 프로젝트 참고자료 전달은 별도 Astra 기획의 제안이다.

## 저장 호환성과 실패

기존 세션·프로젝트 연결 배열, UUID, 노드 위치, 초안을 유지한다. 혼합 연결은 `nodeLinks` 배열에 저장하며, 읽기와 표시에는 `allNodeLinks` 투영을 사용한다. 혼합 연결을 추가하면 작업공간 버전을 2로 표시한다. 현재 앱은 버전 1과 2를 읽는다. 버전 1만 지원하는 구버전 앱은 버전 2 파일을 다시 읽을 때 거부한다. 이미 버전 1을 읽은 구버전 프로세스의 병행 쓰기는 조정하지 않는다.

저장에 실패하면 연결 배열과 작업공간 버전을 변경 전 상태로 복원한다. 손상된 파일을 읽지 못하면 해당 실행 중 저장을 차단한다. 임의로 원본을 비우거나 백업을 만들지 않는다.

## 기능 기획과 남은 범위

별도 사용자 채팅 `01a10165-7955-7420-b67a-34e66382edc5`에서 gpt-6-astra가 기획서를 작성했다. 결과는 `docs/ASTRA-FEATURE-PLAN.md`다. 핵심 권고는 출처를 고정한 전달 묶음, 프로젝트 수신함과 명시적 수신 세션 선택, 수동 참고자료·산출물 포인터, 지속되는 전달 상태 기록이다. 작업 추적·검토 결과 회수·범위 검색·알림은 다음 단계이며 자동 실행은 연동·복구 계약 검증 뒤의 제안이다.

임의의 밀집 그래프에서 모든 연결선의 경로와 라벨이 항상 분리된다는 보장은 없다. 라벨이 빈자리를 찾지 못하면 화살표와 상세 관계를 유지하며 라벨을 생략한다. 포인터 업데이트의 전체 배치 분리는 회귀 테스트에서 유지했으며 FPS나 체감 부드러움의 전후 비교는 측정하지 않았다. 실제 프롬프트부터 모델 응답 완료까지의 E2E, 전체 VoiceOver 탐색, 공증과 외부 배포는 검증하지 않았다.
