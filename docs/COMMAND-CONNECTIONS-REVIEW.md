# Command 드래그 연결 작업 최종 검토

검토일: 2026-10-03. 범위는 네 종류의 프로젝트·세션 연결, 양방향 작업 위치 선택, 연결별 요청 설정, 실행 세션의 스킬 판단, 초안 준비, 화면 단순화이다. 검토자는 이 문서만 변경했다. Swift 소스 변경, 빌드, CUA 조작, 실제 세션 전송은 수행하지 않았다.

## 판정

**검토 범위에서 수용한다.** 소스, 회귀 단언, 최종 100개 테스트, release 패키징, 저장된 네이티브 화면을 직접 확인했다. 통합 담당자가 수행한 네이티브 조작 기록도 검토했다. 검토한 경로에서 잘못된 세션 지정, 자동 전송, 기존 초안 덮어쓰기, 설정 유실 또는 작업 흐름을 막는 미해결 결함을 찾지 않았다.

물리 키보드의 Command 키를 누른 드래그와 실제 운영 세션으로의 프롬프트 전송은 이번 검토에서 런타임으로 검증하지 않았다. 연결 모드 토글을 켠 네이티브 드래그는 공통 좌표·대상 판정·드롭 경로의 근거이며 물리 Command 입력 자체의 근거는 아니다.

## 사용자 동작과 실행 의미

관계의 시작·도착과 실제 작업을 수행할 세션을 구분한다. 사용자는 두 실행 방향을 모두 선택할 수 있다.

| 작업 | 기본 작업 위치 | 참조 대상 |
|---|---|---|
| 참고 | 드래그 또는 연결을 시작한 쪽 | 연결한 상대 쪽 |
| 전달·검토 | 연결한 상대 쪽 | 연결을 시작한 쪽 |
| 직접 요청 | 사용자가 지정한 쪽 | 반대쪽 |

실행 쪽이 프로젝트이면 사용자가 그 프로젝트의 현재 구성원 세션 하나를 선택해야 한다. 프로젝트를 직접 실행하거나 임의의 구성원을 선택하거나 전체 구성원에게 전달하지 않는다. 요청 화면의 `작업`·`참고` 행은 실제 대상 이름을 표시한다. 프로젝트의 담당 세션도 별도로 보인다. 짧은 `출발 쪽`·`도착 쪽` 선택지와 이 행들로 실행 대상을 확인할 수 있으므로 반복적인 A → B 제목은 필요하지 않다.

연결을 만들면 먼저 관계가 저장된다. 요청 창을 닫아도 관계는 남는다. 설정 저장과 초안 준비는 전송이 아니다. 사용자는 받는 세션의 요청 편집기에서 내용을 확인하고 명시적으로 전송한다. 초안 준비 후에는 전체 프로젝트 보드를 유지하면서 받는 세션을 선택한다.

## 소스에서 확인한 보호 동작

- `validatedAction`은 현재 연결 전체와 두 대상의 존재를 검사한다. 프로젝트 담당 세션의 현재 소속을 다시 확인한다. 비동기 참조 읽기 뒤와 초안 저장 직전에도 검증한다.
- 미리보기는 설정·연결 스냅샷과 취소 여부가 일치할 때만 게시한다. 준비 버튼은 표시한 문자열을 그대로 전달한다. 사용자가 확인하지 않은 최신 참조 내용으로 바꾸지 않는다.
- 받는 세션에 다른 비어 있지 않은 초안이 있으면 준비를 중단한다. 설정·초안 저장 실패 시 이전 작업공간을 복구한다. 성공한 저장 뒤에만 선택 대상을 바꾼다.
- 참조 세션은 최근 저장된 assistant 응답의 최대 16,000자를 포함한다. 응답이 없으면 카탈로그 미리보기를 사용하고 그 출처를 구분한다. 전체 대화와 실행 중 내부 상태를 첨부한 것으로 설명하지 않는다. 프로젝트 참조에는 이름·ID·경로가 들어가며 파일과 구성원 대화는 자동으로 첨부하지 않는다.
- 요청을 받는 실제 실행 세션이 적합하고 사용 가능한 스킬을 판단한다. 적합한 스킬이 없으면 일반 방식으로 진행하고, 반드시 필요한 스킬을 사용할 수 없으면 누락 조건을 명시하도록 프롬프트가 안내한다. 별도 로컬 카탈로그 탐색·스킬 선택 UI는 제거됐다.
- 구버전 `.skill`과 필드는 디코딩할 수 있다. `sessionManagedSkills()`는 이를 직접 요청으로 해석하며 실행 방향·담당 세션·비어 있지 않은 프롬프트의 UTF-8 원문을 보존한다. 공백뿐인 구버전 프롬프트만 기본 요청으로 대체한다. 오래된 스킬 이름·경로는 강제하지 않는다. 읽기·저장·생성·준비 경로 모두 같은 변환을 사용한다.
- 연결 수정은 설정을 보존하고 실행 쪽 대상이 바뀌면 담당 세션을 비운다. 연결 삭제는 해당 설정도 지운다. 저장 실패는 전체 상태를 복구한다. 설정이 있는 작업공간은 버전 3으로 저장하며 이미 승격한 상태를 자동으로 낮추지 않는다.
- 연결 드래그 모드는 최초로 인식한 5pt 이상 드래그에서 고정된다. 연결 모드의 위치 이동량은 0이다. 일반 세션 드래그는 위치만 바꾼다. Escape·앱 비활성화·대상 소멸·빈 공간·자기 자신·합성 unassigned 대상은 완료하지 않는다. 기존 같은 방향 context 연결은 재사용한다.
- 아이콘을 누른 뒤 다른 항목을 선택하는 연결도 공통 `completeConnectionDrag` 경로를 사용한다. 연결 관리와 상세의 사용자 동작은 공통 요청 흐름으로 통일했다. 호환성용 `prepareHandoff` API는 남아 있지만 별도 구버전 준비 버튼은 UI에서 제거했다.

## 화면 단순화 평가

주 화면은 작업 흐름, 세션 제목과 상태, 선택한 세션의 실제 대화를 먼저 보여준다. 반복 개수와 구현 용어를 줄였고, 연결 범례·조작 안내는 정보 버튼으로 옮겼다. 상세의 모델·추론 수준·브랜치·경로·ID는 기본으로 접힌 정보 영역에 남아 있다. 선택 대상을 바꾸면 다시 접힌다.

요청 화면은 작업 종류, 요청 내용, 담당 쪽, 실제 작업·참고 대상, 초안 준비에 집중한다. 생성된 전체 전달 내용은 펼쳐서 확인할 수 있다. 자동 스킬 판단 방식은 기본 UI에서 설명하지 않고 생성한 프롬프트에만 포함한다. 요청 편집기는 다음 작업과 개선점을 직접 요청할 수 있으며 자동 분석을 수행한 것처럼 표시하지 않는다.

캔버스·목록·상세는 공통 `SessionStatePill`을 사용한다. live 상태가 아니면 `저장 기록`으로 표시한다. 연결이 끊어지면 저장소가 live 플래그와 상태를 미확인으로 바꾼다. 전역 footer의 실시간 연결과 선택한 저장 세션을 구분하며 데모에서는 실제 전송 없음이 표시된다.

요청·담당 선택·초안 화면 이후 변경은 마지막 작은 위치 이동의 곡선 경로에 한정된다. 위 마지막 곡선 화면은 최종 바이너리 재실행 후 저장됐다. 검토자는 모든 화면을 직접 열어 확인했다.

## 통합 담당자의 네이티브 조작 근거

`evidence/simple-flow-ui-ax.log`를 검토했다. 이 기록은 연결 모드 드래그의 S→S 생성과 검토 초안, P→P의 명시적 WATCH 선택, P→S의 담당 미지정 상태, S→P의 기존 초안 충돌, 설정 닫기 후 관계 유지, 중첩 요청 창에서 준비한 뒤 보드 복귀를 포함한다. 실제 초안 텍스트에는 받는 세션이 적합한 스킬을 판단하는 문구가 있다. 최종 바이너리에서는 연결 모드 ON 드래그로 관계를 만든 뒤 OFF 일반 드래그로 위치만 바꾸는 경로를 다시 확인했다.

일부 구간은 AX 변화 없음과 통합 담당자의 관찰 요약으로 기록되어 있다. 따라서 검토자가 각 마우스 동작을 독립적으로 재현했다고 주장하지 않는다. 실제 운영 세션으로 메시지를 보낸 근거도 아니다.

## 발견 사항과 수정 판정

세 가지 사용자 흐름 결함의 수정을 확인했다.

1. 긴 같은 행 곡선이 가운데 WATCH 카드를 통과했다. 카드 상단 경로로 수정했다. 일반 드래그로 세로 위치를 조금 바꾸면 결함이 재발하여 공통 18pt 범위 안의 위치 변경에도 상단 경로를 유지하도록 보완했다. 32개 이동·방향 조합마다 999개 내부 지점을 검사하며 최종 네이티브 화면도 경로가 카드 밖에 있음을 확인했다.
2. 교차 프로젝트 요청을 준비하면 보드가 받는 프로젝트 하나로 제한됐다. 저장 성공 뒤 전체 프로젝트 보드를 유지하면서 담당 세션만 선택하도록 수정했다. 회귀 단언과 저장된 네이티브 화면을 모두 확인했다.
3. 연결 관리에 구버전 전달 초안 버튼이 남아 공통 요청 경로와 다른 동작을 제공했다. 해당 UI 진입점을 제거했고 최종 소스와 목록 화면을 확인했다.

이전 수동 스킬 선택기의 표시 결함은 사용자가 스킬 판단을 실행 세션에 맡기도록 범위를 바꾼 뒤 종료된 이전 구현의 기록이다. 현재 수용 기준은 선택기 복구가 아니라 현재 프롬프트와 구버전 데이터 호환성이다.

## 검증 한계

물리 Command 키 입력, 실제 운영 세션 전송 및 완료 응답, 모든 임의 노드 배치의 장애물 회피, 렌더링 FPS, 공증·외부 배포를 검증하지 않았다. 작은 위치 변경의 18pt 허용 범위와 샘플 검증을 일반적인 장애물 회피 알고리즘으로 해석하지 않는다. 구버전 앱의 파일 로드 거부는 이미 실행 중인 구버전 프로세스와의 동시 쓰기 조정을 보장하지 않는다.
