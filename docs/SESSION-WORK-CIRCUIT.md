# 세션 상세 작업 회로

세션 상세의 기본 보기는 선택한 요청의 작업 회로다. 프롬프트, 저장된 지침, 도구 호출, 호출 결과, 하위 세션, 공개 메시지와 토큰 계측을 원본 ID로 연결한다. 세션 카드·목록을 두 번 클릭하거나 `작업 회로 보기`를 선택하면 열린다. 프로젝트 상세는 기존 기록 지도를 사용한다.

## 화면과 탐색

- `작업 회로`는 현재 요청을 따라간다. 요청 선택기로 과거 요청을 고정할 수 있다. 명시된 새 요청 ID가 없으면 이전 요청을 현재 요청으로 표시하지 않는다.
- 실행 중·결과 미수신·입력 대기·실패 항목은 개별 노드로 표시한다. 완료한 동일 종류의 항목은 묶음으로 접는다. 펼친 묶음은 24개씩 표시하며 페이지 밖 구성원과 관계도 보존한다.
- 노드를 선택하면 호출 ID, turn ID, 원문, 출처와 연결 근거를 표시한다. `호출 세부 회로`는 선택한 호출과 직접 연결된 항목을 보여준다.
- `이벤트 기록`은 정규화한 작업의 상태 관찰을 60개씩 표시한다. 같은 호출의 시작·완료 관찰은 각각 선택할 수 있다. 기록에 있으면 원시 항목 번호와 원문 위치를 제공한다. 파싱 중복으로 합친 관찰은 상태 이력에 남는다. 이 보기는 원본 JSONL 파일 전체를 줄 단위로 편집하는 화면은 아니다.
- 하위 세션을 열면 같은 읽기 모델로 그 세션의 요청·도구·결과를 표시한다. breadcrumb와 `상위 회로`로 돌아오면 선택한 요청·노드·상태 관찰을 복원한다.
- `기록 지도`는 기존 컨텍스트 지도를 연다. 지도에서 작업 회로로 돌아올 수 있다. 판단·최적화·연결 요청의 초안을 성공적으로 준비하면 담당 세션의 초안 화면을 연다.

## 기록 계약

| 자료 | 연결 근거와 표시 범위 |
|---|---|
| 프롬프트·지침·공개 메시지 | 직접 turn ID를 우선한다. ID가 없으면 확인한 시작·종료 구간을 사용한다. 새 시작의 ID가 없으면 소속을 미확인으로 남긴다. |
| 일반·중첩 명령·MCP 호출 | `call_id`와 native item ID를 연결한다. 시작·완료 표현이 중복돼도 동일 호출로 유지한다. 새 호출 ID는 별도 실행으로 남긴다. |
| 호출 결과 | 명시된 호출 ID에 연결한다. 늦게 도착한 결과는 원래 호출 소속을 보존하고 수신 turn을 별도 관계로 표시한다. 서로 다른 출력은 별도 결과다. |
| 하위 세션·메시지 | 반환된 child ID, DB의 `agent_path`, 명시된 sender·receiver·new thread 필드를 사용한다. 과거 부모·자식 관계와 현재 요청 참여를 구분한다. |
| 파일 변경·이미지 참조 | 기록된 `path`·`changes`·`diff`를 원문 참조로 연결한다. 현재 파일의 존재·내용·hash 또는 사용자 결과를 검증한 것으로 표시하지 않는다. |
| 계측·압축 | 직접 기록된 계측 값과 범위·시각을 사용한다. 압축 기록 자체로 현재 입력 점유율을 추정하지 않는다. |
| 알 수 없는 기록 | 기타 기록과 확인 범위에 남긴다. 원문은 선택할 때 읽는다. 비공개 reasoning·analysis·암호화 필드는 표시하지 않는다. |

명령의 `exit_code: 0`, 도구의 반환 수신, turn의 응답 종료와 사용자 목표 충족은 서로 다른 근거다. 어댑터는 명령 이름이나 메시지 문장만으로 빌드·테스트·실제 기기·배포 검증 관계를 생성하지 않는다. 수집 가능한 공개 기록을 표시하며 서버 내부 동작이나 모델의 비공개 추론을 복원하지 않는다.

## 실시간 상태와 기록 재생

선택한 세션의 기록을 1.5초마다 갱신한다. 처음에는 현재 파일의 고정된 EOF까지 스트리밍으로 읽고 인덱스를 만든다. 이후에는 완결된 JSONL suffix만 읽는다. 파일이 바뀌지 않으면 새 항목을 파싱하지 않는다. 무결성 확인을 위해 읽는 작은 구간은 suffix byte 계측과 별도다.

부분 마지막 줄은 다음 갱신까지 보류한다. 파일 교체·축소·동일 크기 수정·무결성 변경을 발견하면 새 출처 세대로 다시 읽는다. 원문 참조는 파일 식별자·세대·위치·fingerprint를 검사한다. 세션 전환·화면 닫기·작업 취소 후 도착한 응답은 범위와 generation 검사에서 거부한다.

신호는 연결된 현재 세션이 실행 중이고, 선택한 현재 turn과 해당 호출의 실행 기록이 확인된 경로에서만 움직인다. 입력 대기·오류·응답 종료·연결 단절·읽기 오류·과거 기록 재생에서는 신호를 멈춘다. 사용자 신호 버튼, 백그라운드 상태와 Reduce Motion도 애니메이션을 제어한다. 신호의 속도는 처리량·토큰 속도·네트워크 전송량을 뜻하지 않는다.

읽기 실패나 연결 단절 시 마지막 작업 기록과 계측을 유지하고 현재 상태 미확인을 표시한다. 타임라인은 각 관찰 시각의 상태·요약·원문 참조를 투영한다. 이후에 도착한 결과를 이전 재생 시각에 표시하지 않는다. 이벤트 원문 선택과 타임라인 재생은 별도로 저장한다.

연결선은 Canvas로 그리며 노드는 기본 Button으로 선택한다. 노드에는 이름·종류·상태·소속·신선도 접근성 라벨을 제공한다. 전체 VoiceOver 탐색과 모든 키보드 조합은 별도 수동 검증 대상이다. 연결 기하 캐시는 상태·선택·계측 변경 때 재계산하지 않는다.

## 토큰 범위

입력에는 캐시 입력이 포함된다. 출력에는 직접 기록된 추론 출력이 포함된다. 부분 집합을 다시 더하지 않는다. 누락·잘못된 숫자·범위 초과는 0으로 바꾸지 않고 미확인으로 남긴다. 누적값 감소는 새 계측 구간으로 보존한다.

`메인 최근 입력 / 한도`는 마지막 요청 input을 모델 한도로 나눈 값이다. 현재 컨텍스트 점유율은 아니다. 이 비율은 누적 토큰 또는 하위 세션 합계와 별도로 선택한다.

`하위 세션 포함`을 켜면 직접 연결된 하위 세션의 저장 계측을 조회한다. `하위 계측 갱신`으로 다시 조회할 수 있다. 조회 시각과 각 세션의 계측 시각을 표시한다. 같은 범위의 독립 계측이며 하위 포함 여부가 모두 `false`로 명시된 경우에만 합산한다. 포함 여부가 없거나 계측이 누락되면 각 값과 확인 수량을 표시하고 합계를 만들지 않는다. 하위 세션의 입력 한도는 메인 한도와 별도다.

## 구현과 검증 근거

읽기 모델은 `SessionWorkTopology`, 기록 인덱스는 `SessionWorkTopologyLoader`, 화면 상태는 `SessionWorkStore`가 담당한다. 화면은 `SessionWorkTopologyView`와 `CircuitTokenPanel`을 사용한다. 작업 회로 자체는 연결·위치·초안을 저장하거나 프롬프트를 전송하지 않는다. 일반 앱의 기존 작업공간 자동 저장은 별도 동작이다.

[기획·독립 시안](SESSION-DYNAMIC-CIRCUIT-DESIGN.md), [최신 검증 기록](VALIDATION.md), [읽기 전용 실제 기록 probe](../scripts/verify-session-circuit.swift)에 범위와 근거를 기록한다. 최초 진입을 현재 turn부터 보여주는 tail index와 디스크에 유지하는 인덱스는 구현하지 않았다. 첫 인덱스 생성 비용, 이후 갱신 비용과 UI 렌더 성능을 구분해야 한다.
