# 컨텍스트 지도와 겹치기 요청 검토

이 문서는 단순화 적용 전 컨텍스트·겹치기 구현의 검토 기록이다. 아래의 123개 테스트와 바이너리·manifest 해시는 그 시점의 결과다. 이후 단순화의 118개 테스트, 최종 Release 산출물, 변경 후 검토와 네이티브 확인은 [CLEANUP.md](CLEANUP.md)와 [VALIDATION.md](VALIDATION.md)에 기록했다.

검토일: 2026-10-03. 검토 범위는 프로젝트·세션 컨텍스트 지도, 저장된 기록 읽기, 개선 요청 초안, 노드 겹치기와 다음 작업 선택이다. 검토자는 소스·테스트 단언·저장된 네이티브 화면·접근성 로그를 확인했다. 앱을 직접 조작하거나 구현을 변경하지 않았다.

## 현재 판정

**구현된 범위의 소스·회귀·로컬 패키지·데모 조작·실제 기록 읽기를 수용한다. 컨텍스트 지도·겹치기·초안 준비 경로에 미해결 차단 결함은 없다. 앱 전체 수용 판정은 아니다.** 공유 지침 누락, 잘못된 사용량 분류, 프로젝트 더블 클릭 충돌, 참조 추출 지연, 파일 위치 접미사 누락, 기록 묶음 개수 오류의 수정을 확인했다.

최종 소스에서 123개 테스트가 통과했다. 최종 실제 프로젝트 probe는 9개 세션의 100,414,918바이트·11,342개 기록을 3.14초에 읽었다. 최종 정상 앱에서도 프로젝트 지도와 수정된 기록 묶음 개수를 확인했다. 이 결과는 해당 자료의 읽기와 관찰한 UI 흐름에 한정한다. 실제 운영 세션 전송, 임의 대형 자료의 응답성, 렌더링 FPS까지 검증한 것은 아니다.

## 소스에서 확인한 동작

프로젝트·세션 더블 클릭은 중앙 영역에 해당 범위의 컨텍스트 지도를 연다. 기존 대화 상세 패널은 지도에서 숨긴다. 프로젝트 로드는 `CodexCatalog.read(includeArchived: true)`로 보관된 세션을 포함한다. 프로젝트 소속과 경로 경계는 카탈로그에서 판정한다. 별도 회귀 fixture는 일반 카탈로그가 보관 세션을 제외하고, 컨텍스트 카탈로그가 해당 세션을 포함하며, 이름이 비슷한 다른 경로는 같은 프로젝트로 잘못 묶지 않는지 확인한다.

로더는 JSONL 전체를 순회한다. 누락되거나 일부를 읽지 못한 rollout에는 native SQLite 대체 기록을 읽고 출처·중복 가능성·읽기 실패를 표시한다. 본문 미리보기와 전체 본문 읽기를 분리한다. JSONL 본문은 오프셋·길이·fingerprint를 확인한다. SQLite 본문은 `thread_id`와 `item_id`를 함께 조회하고 fingerprint를 확인한다. 같은 item ID를 가진 다른 세션의 본문을 선택하지 않는 단언이 있다. 읽기 경로에는 원본 기록 저장 동작이 없다.

기록은 종류별로 탐색하며 검색·페이지 이동·원문 선택을 제공한다. 지도는 한 페이지에 최대 18개 항목을 표시한다. 긴 본문은 표시 분량을 나누며 나머지 내용에도 접근할 수 있다. 하위 항목은 세션·기록 묶음·도구를 먼저 보여주고 파일 참조는 뒤에 배치한다. 같은 우선순위의 기존 순서는 유지하며 노드나 관계를 제거하지 않는다. 공유 지침은 하나의 노드를 유지하고 적용 세션·프로젝트마다 관계를 표시한다. 검색 결과에는 실제 부모나 기록된 관계가 있는 경우에만 선을 그린다. 검색 결과를 펼치면 실제 부모 경로를 복원한다.

내부 reasoning 본문과 암호화 payload는 미리보기와 전체 본문에서 제외한다. 공개 summary는 보존한다. `AGENTS.md`는 현재 디스크의 지침으로 구분하며 과거 모델 입력이었다고 단정하지 않는다. 토큰 사용량은 지원하는 telemetry 종류·필드·경로에서만 추출한다. 임의 툴 인수와 결과의 token 관련 숫자는 사용량으로 분류하지 않는다. 기록 글자 수를 토큰 수로 환산하지 않으며 누적 사용량 스냅샷도 서로 더하지 않는다.

컨텍스트·툴 개선 요청은 편집 가능한 프롬프트를 만든다. 프로젝트 요청은 사용자가 담당 세션을 명시해야 한다. 준비 직전에 현재 범위, 로드 식별자, 담당 세션 소속, 기존 초안 충돌을 다시 확인한다. 저장 실패 시 전체 작업공간을 복구한다. 성공하면 전체 프로젝트 보드를 유지하고 담당 세션의 요청 편집기로 이동한다. 초안 준비는 전송을 호출하지 않는다.

일반 드래그는 위치 이동이다. 다른 노드와 충분히 겹치면 위치를 원점으로 돌리고 다음 작업 선택을 연다. 판정은 두 사각형 중 작은 면적의 20% 이상 겹침을 사용한다. 세션·프로젝트의 타입을 포함한 ID를 구분한다. 자기 자신과 합성 unassigned 항목은 연결 대상에서 제외한다. 빈 곳에 놓으면 위치를 저장한다. Escape·앱 비활성화·드래그 취소는 위치나 연결을 저장하지 않는다.

겹치기는 선택 전까지 제안 상태다. 취소하면 작업공간을 바꾸지 않는다. 참고·전달·검토·직접 요청 중 하나를 선택하면 같은 방향의 context 연결을 재사용하거나 생성한다. 연결과 실행 설정을 함께 저장하고 실패 시 복구한다. 이후 기존 공통 요청 화면에서 담당·요청·초안을 확인한다. 소속 변경, 프로젝트 이동, 자동 전송을 수행하지 않는다.

## 발견 사항과 수정 확인

1. **공유 지침 표시 누락:** `parentID`만으로 하위 노드를 구성하여 두 번째 세션과 프로젝트에 적용되는 공유 지침이 보이지 않았다. 실제 outgoing 관계의 대상도 중복 없이 투영하도록 수정했다. 현재 소스에서 적용 관계가 화면 후보에 들어가는 것을 확인했다.
2. **잘못된 사용량 분류:** 모든 기록의 token 관련 숫자를 사용량으로 수집했다. 지원하는 `token_count`·`token_usage_record`와 허용한 필드·경로로 제한했다. 툴 인수·출력·일반 메타데이터의 유사 숫자를 제외하고 원문에는 보존하는 회귀 단언을 확인했다.
3. **사이드바 프로젝트 더블 클릭 충돌:** 단일 Button 동작의 `closeContext()`와 동시 더블 탭이 충돌했다. 배타적인 더블·단일 탭으로 바꾸고 접근성 동작을 유지했다. 수정 후 통합 담당자의 접근성 로그에 프로젝트 지도 진입과 3개 세션·33개 항목이 나타난다.
4. **선과 카드의 충돌:** 컨텍스트 하위 노드를 한 열로 정렬했다. 저장된 프로젝트·세션 화면에서 계층 곡선이 카드 왼쪽 공간을 통과하는 것을 직접 확인했다.
5. **대형 기록 읽기 지연 — 소스 수정 및 실제 읽기 확인:** 통합 담당자는 약 95 MB·9개 세션의 실제 프로젝트 probe에서 참조 정규식의 ICU 실행이 CPU를 지속 사용한다고 보고했다. 실행은 종료값 130으로 중단됐다. 이는 성공한 로드나 성능 측정값이 아니다. 정규식을 UTF-8 순회로 교체한 소스를 검토했다. 1 MB가 넘는 슬래시 반복 출력에서 전체 본문 길이, 일반 파일, 공백을 포함한 SKILL.md 경로, plugin 참조를 확인하는 회귀 단언이 통과했다. 추가 검토에서 `/tmp/source.swift:42`와 같은 위치 접미사가 파일 참조를 누락시키는 회귀를 발견했다. 파일 후보의 숫자형 `:line[:column]`만 제거하도록 수정했고 두 형태와 plugin URI 원문 보존을 회귀 fixture에서 확인했다. 최종 프로젝트 probe는 9개 출처·11,342개 기록·100,414,918바이트를 3.14초에 읽었으며 읽기 문제는 0개다. 최대 RSS는 539,787,264바이트다. 측정은 실제 기록의 CLI 읽기이며 화면 렌더링 시간이 아니다.
6. **기록 묶음 개수 오류:** 화면 부모를 기준으로 세어 도구 호출 묶음에는 구조용 도구 개수가 나오고 결과 묶음은 0으로 나왔다. `sessionID`와 기록 종류를 기준으로 실제 기록 노드를 합산하도록 수정했다. 구조·참조 노드는 제외한다. 도구 자체의 호출 개수와 호출·결과 본문 크기는 유지한다. 회귀 단언은 호출 묶음 2개·결과 묶음 1개와 정확한 글자 수를 확인한다. 최종 실제 앱 로그에는 해당 세션의 호출 768개·결과 767개가 표시된다.

다른 검토자가 지적한 사라진 범위의 최적화 허용과 검색 결과의 잘못된 연결도 현재 소스에서 수정된 것을 확인했다. 로드 완료, 개선 요청 생성, 초안 준비에서 범위 존재를 다시 검사한다.

데모 접근성 로그에서 프로젝트 개선 요청은 처음에 담당이 미지정이며 초안 준비가 비활성화돼 있다. 이후 사용자가 편집한 문장이 DESIGN 요청 편집기에 표시된다. 네 방향 조합은 P→P, P→S, S→P, S→S의 다음 작업 화면으로 기록된다. 검토를 선택한 뒤 공통 요청 시트가 유지되며 MODELS 초안 준비까지 이어진다. 따라서 이전 시트 종료가 새 요청을 지우는 전환 결함은 이 관찰 흐름에서 재현되지 않았다.

검토자는 저장된 다섯 화면을 직접 열어 확인했다. 마우스 조작과 취소·복귀의 실행 주체는 통합 담당자다. 일부 변화 없음과 동작 순서는 담당자의 관찰에 의존한다. 취소의 데이터 보존과 저장 실패 복구는 별도 상태·저장소 회귀 단언으로 확인했다.

CLI와 GUI는 읽은 시점이 다르고 대상 대화가 계속 기록되는 중이므로 노드 수와 호출·결과 수가 같아야 한다고 판정하지 않는다.

## 별도 모니터링 관찰과 시간 경계

정상 앱 확인 중 일시적인 live 상태 차이가 관찰됐다. 통합 담당자의 초기 GUI에는 열린 세션이 0개로 표시됐지만 같은 시기의 CLI probe는 11개를 보고했다. 수동 재연결 직후에도 0개가 보였으나, 종료 전 새로 읽은 CUA 상태에서는 열린 세션 11개·실행 중 1개로 회복됐다. 따라서 지속적인 GUI 실패로 판정하지 않는다. footer 문구 변경 후 저장한 최종 `context-final-caption-ui-ax.log`의 시작과 안정 상태에는 모두 열린 세션 11개가 기록돼 있으며 footer는 실행 2·입력 대기 0을 표시한다. 따라서 최신 로그 자체를 0→11 전환의 증거로 사용하지 않는다. 초기 0개 표시와 그 뒤 회복의 순서는 통합 담당자의 앞선 관찰에 근거하며 지연 원인은 아직 확인하지 못했다. 이 시간 차이를 저장된 기록의 컨텍스트 읽기 성공과 구분한다.

footer의 `실시간`은 initialize 연결만으로 갱신 스트림까지 정상인 것처럼 보일 수 있었다. 최종 소스는 이를 `Codex 연결`로 바꿨다. 이 문구 변경은 연결 상태를 더 좁게 설명할 뿐, 관찰한 지연의 원인을 수정한 근거가 아니다. 모니터링의 취소 후 연결 상태 유지 가능성도 이번 범위에서 수정하지 않았다. 컨텍스트·겹치기 기능의 수용을 앱 전체 모니터링 동작에 대한 수용으로 확장하지 않는다.

## 검증 한계

현재 근거는 로컬 소스·자동 회귀·로컬 ad-hoc 서명·데모 네이티브 상태를 구분한다. 현재 모델에 실제 전달된 모든 입력, 현재 가용 도구·스킬 전체, 임의 대형 프로젝트의 응답성, 모든 자유 배치의 장애물 회피, 렌더링 FPS, 실제 운영 세션 전송과 완료 응답, 공증·외부 배포를 검증하지 않았다.
