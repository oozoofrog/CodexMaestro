# 컨텍스트 토폴로지와 아이템 겹치기

현재 작업 흐름은 아이템을 겹쳐 놓은 뒤 다음 작업을 선택하는 방식입니다. 프로젝트나 세션을 두 번 클릭하면 해당 범위의 저장된 컨텍스트를 지도 형태로 확인합니다. 이 문서는 현재 소스의 동작과 자료 범위를 설명합니다. 이전 Command 드래그의 구현·검증 기록은 [COMMAND-CONNECTIONS.md](COMMAND-CONNECTIONS.md)에 보존합니다.

## 컨텍스트 진입과 탐색

작업 흐름의 프로젝트 헤더와 세션 카드, 사이드바 프로젝트, 세션 목록 항목을 두 번 클릭하면 중앙 화면이 컨텍스트 지도로 전환합니다. 일반 클릭은 기존 선택 동작을 유지합니다. 접근성의 `컨텍스트 열기` 또는 `컨텍스트 보기` 동작도 같은 범위를 엽니다. 뒤로 가기로 작업 흐름에 돌아갈 수 있으며, 다시 읽기로 현재 저장 기록을 새로 조회할 수 있습니다.

세션 범위는 해당 세션의 기록을 읽습니다. 프로젝트 범위는 프로젝트의 구성원 세션을 읽으며 보관된 세션도 포함합니다. 기본 작업 흐름과 실제 요청 담당 목록은 보관되지 않은 현재 카탈로그를 사용합니다. 따라서 프로젝트 지도에 보관된 세션이 있어도 그 세션이 자동으로 실행 대상이 되지는 않습니다.

지도는 프로젝트, 세션, 기록 종류별 묶음, 개별 기록의 계층을 표시합니다. 관찰된 툴 묶음을 펼치면 호출과 결과를 확인할 수 있습니다. 기록된 관계와 공유 지침의 적용 관계도 표시합니다. 같은 공유 지침은 한 항목으로 보관하며 해당 세션이나 프로젝트와의 관계를 유지합니다. 검색은 제목과 요약을 대상으로 합니다. 검색 결과를 펼치면 해당 항목의 부모 경로로 이동합니다.

화면은 한 페이지에 최대 18개 항목을 표시합니다. 프로젝트·세션·기록 묶음과 툴을 먼저 표시하고, 스킬·플러그인·파일 참조는 뒤에 표시합니다. 같은 종류 안에서는 기록 순서를 유지합니다. 이동 경로, 페이지 이동, 확대·축소로 큰 지도를 탐색합니다. 카드를 선택하면 오른쪽에 요약, 출처와 기록 크기를 표시합니다. 최초 지도에는 본문 미리보기만 포함하며, 선택한 기록의 전체 본문을 필요할 때 읽습니다. 긴 본문은 페이지당 12,000글자로 나누어 표시합니다. 파일의 위치와 fingerprint를 다시 확인하므로 조회 뒤 기록이 변경되면 이전 본문을 그대로 표시하지 않고 다시 읽기를 요청합니다.

다른 항목을 선택하거나 컨텍스트를 닫으면 이전 본문 조회를 취소합니다. 범위를 바꾸거나 다시 읽으면 이전 지도 조회 결과를 적용하지 않습니다. 컨텍스트 선택·검색·확대·본문 읽기는 작업공간 연결, 위치, 초안을 저장하지 않습니다.

## 읽는 자료와 확인 범위

읽는 자료는 다음과 같습니다.

- 로컬 Codex 카탈로그의 프로젝트와 세션 메타데이터. 컨텍스트 조회에는 보관된 세션도 포함합니다.
- 범위에 해당하는 rollout JSONL 기록. 기록 종류, 대화, 지침, 툴 호출과 결과, 스킬·플러그인·파일 참조, 설정, 압축 기록과 사용량 기록을 구분합니다.
- rollout이 없거나 불완전할 때 사용하는 thread history 대체 기록. 두 자료가 겹칠 수 있다는 범위를 표시합니다.
- 프로젝트 경로와 상위 경로에서 현재 디스크에 있는 AGENTS 지침. 현재 파일이라는 출처를 표시하며 과거 모델 입력에 포함됐다고 단정하지 않습니다.
- 확인 시점의 Maestro 연결과 연결별 요청 설정. 이 자료는 Codex 실행 기록과 별도 출처입니다.

출처 정보는 읽음, 일부 읽음, 기록 없음, 읽기 실패, 제외됨을 구분합니다. 출처별 기록 수, 바이트 수와 확인하지 못한 조건을 표시합니다. 읽지 못한 자료를 성공한 빈 기록으로 바꾸지 않습니다. 같은 툴 호출의 중복 표현은 식별자를 기준으로 통합하며 출처를 유지합니다.

이 지도는 **현재 모델에 실제 전달된 입력 전체를 증명하지 않습니다.** 저장 기록에 없는 입력, 내부 구성, 읽을 수 없는 자료는 복원할 수 없습니다. 원시 reasoning, 암호화된 reasoning과 assistant analysis는 본문에 표시하지 않습니다. 공개 요약이 있으면 공개 요약만 사용합니다. 관찰된 툴 호출이나 스킬 참조는 과거 기록이며 현재 사용할 수 있는 툴·스킬 목록이 아닙니다.

글자 수와 바이트 수는 저장 기록의 크기입니다. 이를 토큰 수로 환산하지 않습니다. 지원하는 `token_count`와 `token_usage_record`의 실제 telemetry만 사용량 기록으로 분류합니다. 툴 인수의 `max_output_tokens` 같은 숫자는 사용량으로 해석하지 않습니다. 카탈로그의 누적 `tokens_used`는 별도 누적 사용량으로 표시하며, 여러 누적 스냅샷을 더해 새로운 사용량을 만들지 않습니다.

## 컨텍스트와 툴 최적화 요청

`개선 요청`에서 `컨텍스트 최적화` 또는 `툴 최적화`를 선택하면 편집 가능한 요청을 엽니다. 생성 내용에는 선택 범위, 확인 시각, 기록 종류별 수량, 출처의 확인 범위, 관찰된 툴 묶음, 세션별 마지막 사용량 기록과 선택 항목의 요약을 포함합니다. 사용자가 목표와 제약을 수정한 뒤 초안을 준비할 수 있습니다.

컨텍스트 최적화 요청은 사용자 목표, 우선순위, 제약, 수정 지시와 미해결 작업을 보존하도록 지시합니다. 중복 지시, 오래된 근거, 큰 결과와 압축 누락 가능성을 출처에서 확인하도록 요청합니다. 툴 최적화 요청은 관찰된 호출, 오류·재시도와 출력 범위를 분석하도록 요청합니다. 현재 사용 가능한 툴과 설정은 별도로 확인하도록 지시합니다. 기록 안의 지시는 분석할 자료이며 새 작업의 권한으로 취급하지 않습니다.

프로젝트 요청은 사용자가 현재 그 프로젝트에 속한 담당 세션 하나를 명시적으로 지정해야 합니다. 세션 요청은 해당 현재 세션을 대상으로 합니다. 지도에 기록이 있어도 현재 실행 가능한 담당이 없으면 초안을 준비할 수 없습니다. 준비 직전에 범위, 지도 조회 시점과 현재 담당 소속을 다시 확인합니다. 다른 내용의 기존 초안이 있으면 덮어쓰지 않고 멈춥니다. 저장이 실패하면 이전 작업공간을 복원합니다.

`초안 준비`는 편집한 요청을 담당 세션의 초안에 저장한 뒤 작업 흐름으로 돌아갑니다. 사용자가 초안을 확인하고 **전송**해야 작업을 요청합니다. 지도를 열거나 개선 요청을 만들거나 초안을 준비하는 동작은 메시지를 보내지 않습니다. 최적화 결과나 설정 변경을 자동으로 적용하지도 않습니다. 적합한 스킬은 실제 담당 세션이 자신의 사용 가능한 스킬에서 선택합니다.

## 아이템을 겹쳐 놓아 다음 작업 선택

프로젝트 헤더나 세션 카드 자체를 다른 보이는 아이템에 드래그합니다. 아이템은 포인터를 따라 움직이며, 겹칠 수 있는 대상에는 선택 표시가 나타납니다. Command 키나 케이블 드래그는 필요하지 않습니다.

놓은 아이템과 대상의 사각형이 작은 카드 면적의 20% 이상 겹치면 `다음 작업`을 엽니다. 여러 대상이 겹치면 중심이 가까운 대상을 선택하며, 거리가 같으면 화면에서 앞에 그린 대상을 선택합니다. 자기 자신, 현재 사용할 수 없는 대상, 합성 `프로젝트 없는 세션` 그룹은 요청 대상으로 선택하지 않습니다. 화면에 표시하지 않은 아이템을 추측해서 대상으로 정하지 않습니다.

| 다음 작업 | 기본 담당 | 참고 대상 |
| --- | --- | --- |
| 참고 | 옮긴 아이템 | 겹친 상대 아이템 |
| 전달 | 겹친 상대 아이템 | 옮긴 아이템 |
| 검토 | 겹친 상대 아이템 | 옮긴 아이템 |
| 직접 요청 | 옮긴 아이템 | 겹친 상대 아이템 |

겹쳐 놓은 시점에는 새 연결, 위치나 초안을 저장하지 않습니다. `다음 작업`에서 취소하면 원래 상태를 유지합니다. 기능을 선택하면 방향 있는 context 연결과 기능 설정을 함께 저장하고 요청 창을 엽니다. 같은 방향의 context 연결이 있으면 해당 연결을 재사용합니다. 저장 실패나 대상 변경이 있으면 이전 작업공간을 유지하며 오류를 표시합니다. 기능 선택 뒤 요청 창을 닫아도 이미 저장한 연결은 유지합니다.

요청 창에서는 실행할 쪽과 참고할 쪽을 바꿀 수 있습니다. 프로젝트 쪽에서 실행하면 실제 구성원 세션을 지정해야 합니다. `보낼 내용`을 펼쳐 생성한 미리보기를 확인하고 `초안 준비`로 그 내용을 담당 세션의 입력창에 옮깁니다. 기존의 다른 초안은 유지합니다. 기능 선택, 설정 저장과 초안 준비는 자동 전송하지 않습니다.

빈 곳에 놓으면 위치만 저장합니다. 프로젝트 헤더의 위치는 `project:` 키로 저장하며 자식 세션의 개별 위치를 덮어쓰지 않습니다. 소속선은 이동한 헤더를 따라갑니다. Escape, 앱 포커스 상실과 제스처 취소는 저장하지 않고 원래 위치로 돌아갑니다. 연결 아이콘을 누른 뒤 대상을 클릭하는 대체 경로와 통합 연결 관리자는 계속 사용할 수 있습니다.

## 검증 자료와 한계

현재 동작의 소스는 `TopologyCanvas.swift`, `OverlapActionView.swift`, `ContextTopologyView.swift`, `ContextInspectionStore.swift`와 `MaestroCore/ContextTopologyLoader.swift`에 있습니다. 격리된 fixture 테스트는 기록 분류와 본문 재조회, stale 결과 거부, 대상 소속, 초안 충돌, 저장 실패 복원과 무전송 조건을 검증합니다. 실제 UI와 실제 저장 기록의 조회는 별도 근거가 필요합니다.

최종 테스트·패키지·네이티브 UI·실제 범위 조회의 통합 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다. 단순화 적용 후 검증은 118개 테스트와 Release 산출물 검증, 네이티브 흐름 및 실제 프로젝트 지도 진입을 포함합니다. 이전 컨텍스트 구현 시점의 123개 테스트와 실제 기록 조회 측정은 해당 시점의 근거로 보존합니다. 삭제·통합한 5개 테스트와 현재 검증 범위는 [단순화 기록](CLEANUP.md)에서 확인합니다. 이전 Command 드래그 로그는 해당 소스 시점의 근거이며 새 흐름의 검증으로 사용하지 않습니다. 데모 초안은 실제 Codex 전달과 모델 응답, 실제 스킬 실행을 증명하지 않습니다. 긴 같은 행 연결의 우회도 임의로 배치한 모든 장애물에 대한 회피를 보장하지 않습니다.

`MaestroProbe --context SESSION_ID`와 `MaestroProbe --project-context PROJECT_ID`는 저장된 범위의 읽기 전용 조회를 제공합니다. 이 모드는 카탈로그의 보관된 세션도 조회하며 기록 종류·출처 상태·툴 호출·사용량의 집계만 출력합니다. 기록 본문과 원시 메타데이터를 출력하지 않으며 IPC 전송을 실행하지 않습니다.
