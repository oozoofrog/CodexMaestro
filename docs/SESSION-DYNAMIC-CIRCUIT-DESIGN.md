# 세션 상세 동적 회로 기획·디자인

**세션 상세의 기본 보기를 현재 프롬프트 중심의 작업 회로로 구성한다.** 메인 세션이 받은 입력, 실행한 도구, 위임한 하위 세션, 수신한 결과, 공개 응답과 토큰 계측을 같은 화면에서 추적한다. 각 노드를 선택하면 원문과 연결 근거를 확인한다.

작성일은 2026-10-04다. 이 문서는 [앞선 작업 구조 조사](SESSION-WORK-TOPOLOGY-PLAN.md)의 기록 계약을 화면 설계로 구체화한다. 이번 산출물은 기획과 독립적인 디자인 시안이다. 네이티브 앱에 동적 회로 기능을 연결한 결과를 뜻하지 않는다.

후속 네이티브 구현의 실제 동작과 한계는 [세션 상세 작업 회로](SESSION-WORK-CIRCUIT.md)에 기록한다. 아래 시안 검증은 후속 구현의 런타임 검증과 별도다.

시안은 외부 요청이나 실제 명령을 실행하지 않는다. 실제 세션에 프롬프트를 전송하지 않는다. 합성 자료임을 상단과 하단에 계속 표시한다.

## 2. 세션 상세를 열었을 때의 동작

1. 실행 중인 turn의 현재 프롬프트와 메인 세션을 먼저 표시한다. 실행 중인 turn이 없으면 최근 turn을 열고 종료 상태를 명시한다.
2. 현재 실행, 결과 미수신, 입력 대기, 오류 노드를 우선 펼친다. 완료한 반복 호출은 수량과 범위를 표시한 묶음으로 접는다.
3. 현재 turn의 입력·호출·위임·결과를 ID로 연결한다. 최근 시각만을 근거로 다른 turn의 호출이나 과거 하위 세션을 붙이지 않는다.
4. 사용자가 노드를 선택하면 오른쪽 상세 패널을 갱신한다. 새 이벤트가 와도 선택과 화면 위치를 유지한다.
5. 사용자가 도구 또는 하위 세션의 상세 회로를 열면 해당 범위만 펼친다. 상단 경로에서 메인 회로로 돌아간다.

기록이 많은 세션에서도 전체 기록을 버리지 않는다. `이벤트 기록`에서 원시 항목과 과거 turn을 탐색하고, `확인 범위`에서 읽은 자료·누락·갱신 상태를 확인한다. 회로는 현재 작업을 보는 기본 화면이고, 전체 기록 탐색은 같은 상세 화면에 유지한다.

## 3. 화면 구성

| 영역 | 표시 내용 | 설계 목적 |
| --- | --- | --- |
| 창 상단 | 앱 이름, 시안 표시, 테마 | 제품 화면과 합성 자료의 범위를 구분 |
| 왼쪽 | 선택 프로젝트·세션, 현재 turn의 하위 세션 | 현재 범위 유지와 분기 접근 |
| 상세 헤더 | 세션 제목, 모델·reasoning effort, turn ID, 세션 상태 | 무엇을 관찰하는지 표시 |
| 프롬프트 띠 | 현재 사용자 요청 원문 | 작업의 출발점 유지 |
| 중앙 회로 | 입력·컨텍스트 / 프롬프트·세션 / 도구·하위 세션 / 결과·검증 | 병렬 분기와 결과 귀환을 같은 공간에서 추적 |
| 오른쪽 패널 | 선택 항목의 역할·ID·인수·결과·출처·관련 노드 | 간결한 회로와 상세 원문을 연결 |
| 회로 아래 | 최근 이벤트, 기록 신선도, 계측 시각 | 현재 상태와 마지막 관찰을 구분 |
| 토큰 띠 | 입력·캐시 입력·출력·최근 입력/한도, 하위 세션 합산 | 비용과 입력량을 중복 없이 비교 |
| 이벤트 타임라인 | 현재 위치, 상태 변화, 재생·다음 이벤트 | 과거 상태와 현재 상태를 구분 |

네이티브 구현의 기본 폭은 1440px 정도를 기준으로 검토한다. 작은 창에서는 상세 패널을 아래로 이동하고, 더 좁은 폭에서는 회로를 두 열로 재배치한다. 텍스트를 축소하는 방식으로 밀도를 맞추지 않는다. 실제 SwiftUI 구현에서는 고정 픽셀 대신 macOS 텍스트 스타일과 사용자 글자 크기를 사용한다.

## 4. 작업 범위와 노드 계약

시안의 16개 노드는 작업 **종류**를 보여주는 예시다. 실제 구현에서는 모든 명령·MCP 호출·위임·결과가 stable ID를 가진 개별 인스턴스다. 종류별 노드 하나에 여러 실행 결과를 덮어쓰지 않는다. 묶음에는 구성원 수, 시간 범위, 상태 분포와 미수신 결과 수를 표시하며 구성원을 모두 펼칠 수 있어야 한다.

| 작업 종류 | 회로에서 보여줄 것 | 연결과 확인 기준 |
| --- | --- | --- |
| 현재 프롬프트 | 원문, 메시지 ID, 소속 turn | 직접 `turn_id` 우선. 구간으로 연결한 경우 그 근거 표시 |
| 지침·컨텍스트 | 시스템·개발자·사용자 지침과 사용한 자료 | 원본 위치·역할·확인 범위. 현재 모델 내부 입력 전체로 일반화하지 않음 |
| 파일·자료·스킬·플러그인 | 참조 대상과 실제 읽기 결과 | 경로 언급, 참조, 본문 읽기를 구분 |
| 메인 세션 | 모델·effort, 세션 상태, 선택한 turn | IPC 상태와 기록의 수명주기를 별도 보존 |
| 도구 호출 | 이름, 인수, call/item ID, 호출 시각 | 결과를 같은 `call_id` 또는 native item ID로 연결 |
| 구조화된 명령 | command, cwd, process ID, 종료값, 실행 시간 | 중첩 `CommandExecution` 항목 우선. 코드 문자열에서 실행을 추정하지 않음 |
| 구조화된 MCP 실행 | server, tool, arguments, result, 오류, 실행 시간 | 중첩 `McpToolCall`과 직접 기록을 중복 없이 연결 |
| 외부 API·브라우저·미디어 등 기타 도구 | 원래 도구 종류, 인수 요약, 결과 | 동일 호출 계약을 사용. 기록되지 않은 내부 작업은 미확인 |
| 호출 결과 | 반환 수신, 실행 성공·실패, 본문 위치 | 반환 수신과 성공을 분리. `status: completed`만으로 성공을 판정하지 않음 |
| 입력 대기·승인 대기 | 질문·대기 대상·시작 시각 | 명시된 상태만 사용. 응답을 임의 생성하거나 제출하지 않음 |
| 하위 세션 | 위임 요청·자식 ID·현재 상태·보고 | `parent_thread_id`와 위임/메시지 ID. 존재와 현재 turn 참여를 구분 |
| 하위 세션 간 메시지 | 송신·수신 대상·요청·보고 | 저장된 메시지 ID와 전달 결과. 발신만 확인되면 수신·소비는 미확인 |
| 공개 진행 보고 | 실제 공개 메시지와 생성 시각 | 내부 reasoning 대신 사용자에게 공개한 메시지만 표시 |
| 입력 캐시 | 기록된 cached input 계측 | 입력의 부분 집합. 의미 판단 캐시·자료 재사용과 구분 |
| 컨텍스트 압축 | 압축 이벤트와 해당 turn | 압축 이벤트 존재를 표시. 숨겨진 입력이나 내부 reasoning을 복원하지 않음 |
| 토큰 계측 | 계측 종류·값·범위·시각·출처 | 직접 기록한 수치만 사용. 값 없음은 `미확인` |
| 검증 근거 | 소스·빌드·테스트·설치·런타임·실제 기기·배포 | 각 근거의 대상·시각·출처를 구분. 명령 성공만으로 사용자 결과를 인정하지 않음 |
| 산출물 | 파일·PR·문서·이미지 등의 참조 | 경로 언급, 생성 확인, 내용 확인, 배포를 구분 |
| 최종 응답·turn 종료 | 공개 응답, 종료/중단 이벤트 | 응답 종료와 목표 충족을 분리 |
| 알 수 없는 기록 | 원래 타입·ID·출처, 파싱 범위 | 누락하지 않고 이벤트 기록과 확인 범위에 남김 |

`모든 작업`은 수집 가능한 공개 실행과 기록을 뜻한다. 모델의 비공개 reasoning, 암호화된 본문, 기록되지 않은 서버 내부 과정은 대상에 포함해 복원하지 않는다. 누락과 비공개 범위는 화면에서 명시한다.

## 5. 동적 회로의 신호 규칙

회로는 얇은 직교 연결선과 작은 방향 신호를 사용한다. 입력 선은 점선, 위임·보고 선은 별도 색, 토큰 계측 선은 점선 형태로 구분한다. 색과 함께 관계 라벨·방향·상태 텍스트를 제공한다.

| 상태 | 노드와 선 | 의미 |
| --- | --- | --- |
| 실행 중 | 밝은 상태 점과 선택 가능한 노드. 관찰된 실행 경로에만 흐르는 신호 | 해당 작업의 현재 실행을 확인 |
| 결과 대기 | 결과 미수신 라벨과 마지막 호출 시각 | 호출은 확인했지만 결과는 미확인 |
| 입력 대기 | 사각 상태 점, 대기 대상 강조, 관련 신호 정지 | 사람 또는 명시된 입력을 기다림 |
| 오류 | 마름모 상태 점, 실패한 호출·결과 강조 | 종료값 또는 결과 오류 필드로 확인한 실패 |
| 결과 있음 | 조용한 선과 결과 라벨 | 결과 수신. 결과의 성공 여부는 별도 표시 |
| 응답 종료 | 신호 정지, 공개 응답과 종료 시각 유지 | turn 종료. 목표 충족 여부는 별도 |
| 연결 끊김·자료 갱신 지연 | 신호 정지, 마지막 관찰과 마지막 계측 유지 | 현재 상태는 미확인. 마지막 수치를 0으로 바꾸지 않음 |
| 재시도 | 이전 오류 노드 유지, 새 attempt와 호출 ID 추가 | 새 실행. 기존 실패를 성공으로 덮어쓰지 않음 |

신호의 속도와 개수는 실제 처리량·토큰 속도·네트워크 전송량을 나타내지 않는다. 계측이 없는 상황에서 움직임으로 수치를 암시하지 않는다. IPC에서 세션이 실행 중이어도 개별 작업을 식별할 근거가 없으면 메인 세션 상태만 갱신한다.

시안의 타임라인에는 요청 수신, 컨텍스트, 병렬 실행, 입력 대기, 도구 오류, 새 호출, 결과 취합, 검증, 응답 종료의 9개 합성 상태를 넣었다. 자동 재생은 입력 대기·오류·종료에서 멈춘다. 사용자는 다음 이벤트를 직접 선택한다. 실제 제품의 실시간 관찰과 과거 이벤트 재생은 표시와 상태 저장 공간을 분리한다.

## 6. 노드 선택과 하위 회로

한 번 선택하면 오른쪽 상세 패널을 연다. 도구나 하위 세션을 실행하는 행동은 발생하지 않는다. 패널에는 원문, stable ID, 해당 결과, 관련 노드와 출처를 표시한다. 근거가 없는 필드는 채우지 않는다.

도구 세부 회로는 요청 → 인수 → 실행 → 결과 → 메인 세션 반환으로 구성한다. 결과 근거는 별도 원본 참조로 연결한다. 여러 도구를 포함하는 `exec`도 기록에 실제로 나타난 내부 실행을 구분할 수 있어야 한다.

하위 세션 회로는 위임 프롬프트, 해당 세션의 컨텍스트, 모델, 도구, 결과, 보고, 산출물, 계측을 표시한다. 상위 회로에는 요약 노드 하나를 유지한다. 자식의 자식도 같은 방식으로 내려간다. 다른 turn에서 생성한 하위 세션은 `과거 하위 세션` 범위에 두고 현재 실행인 것처럼 움직이지 않는다.

시안은 메인 16개 노드·20개 연결, 하위 세션 두 개의 8개 노드 회로, 명령·MCP의 6개 노드 회로를 제공한다. 하위 회로는 모두 합성 자료다.

## 7. 토큰 계측과 합산

**입력 + 출력만으로 총 사용량을 계산한다.** `cached_input_tokens`는 입력에 포함한다. `reasoning_output_tokens`는 출력에 포함한다. 네 값을 모두 더하지 않는다.

시안의 기본 상태는 메인 turn 입력 24,380, 캐시 입력 21,500, 출력 2,140, 추론 출력 840이다. 총량은 26,520이다. 이 수치는 데이터 계약을 검토하기 위한 예시다.

| 계측 | 계약 |
| --- | --- |
| 입력·출력 누적 | `sessionID`, `turnID`, 기준 시점, 계측 시각과 누적 범위를 함께 보존 |
| 캐시 입력 | 입력의 부분 집합. 비율 분모는 같은 범위의 입력 |
| 추론 출력 | 출력의 부분 집합. 내부 reasoning 본문을 표시하는 근거로 사용하지 않음 |
| 최근 입력 / 한도 | 마지막 요청의 input과 해당 모델 context window를 각각 확인한 경우에만 표시 |
| 하위 세션 포함 | 직접 계측한 메인·자식의 중복 없는 범위를 합산. 포함 범위·누락·각 계측 시각을 표시 |
| 비용·속도 | 가격표·요청별 시간·계측 근거가 확보된 별도 기능. 이번 시안에 추정치를 넣지 않음 |

`최근 입력 / 한도`는 **현재 컨텍스트 점유율이 아니다.** 시안의 19,800 / 128,000 = 15.5%는 마지막 요청 입력 대비 예시 모델 한도다. 로그 바이트 수나 화면에 보이는 문장 길이로 토큰을 추정하지 않는다. 마지막 요청 input과 model window 중 하나가 없으면 비율은 미확인이다. 압축 이벤트 하나만으로 점유율이 감소했다고 판단하지 않는다.

누적 계측이 세션 전체 값인지 turn 값인지 어댑터에서 구분한다. turn 값을 만들 때는 같은 세대의 명시된 기준점을 사용한다. 수치 감소·파일 교체·세션 재개가 있으면 새 계측 구간을 만든다. 이전 구간과 단순 차감해 음수나 잘못된 델타를 만들지 않는다.

하위 세션 합산은 상위 수치가 이미 자식을 포함하는지 확인한 뒤 허용한다. 중복 범위를 판별할 수 없으면 합계를 표시하지 않는다. 계측 없는 자식은 0이 아니다. `계측한 3개 / 전체 4개`처럼 확인 범위를 표시한다. 서로 다른 시각의 합계이면 그 사실을 표시한다.

각 세션의 입력 한도는 별도다. 하위 세션을 포함해 입력·출력을 더해도 메인 세션의 `최근 입력 / 한도` 비율은 바꾸지 않는다. 도구 선택 패널에 메인 토큰을 도구별 사용량처럼 표시하지 않는다.

## 8. 실제 자료 수집과 연결 모델

기존 기록 지도와 판단 입력을 유지하고, 별도 읽기 모델 `SessionWorkTopology`를 추가하는 방향이 적절하다. 화면은 원시 기록 ID를 참조한다. 의미 제목을 생성하더라도 원시 작업과 관계를 대체하지 않는다.

자료는 다음 순서로 변환한다.

1. IPC와 카탈로그에서 선택 세션과 실시간 상태를 읽는다.
2. rollout의 완결된 레코드를 스냅샷 끝까지 읽고, 이후 추가된 레코드만 읽는다.
3. 직접 item과 중첩 `event_msg.item_completed.item`을 정규화한다. 알 수 없는 타입도 보존한다.
4. stable ID로 항목을 병합하고 `turn_id`, `call_id`, native item ID, `parent_thread_id`로 관계를 만든다.
5. 수명주기·결과 수신·실행 성공·입력 대기·계측 신선도를 각각 계산한다.
6. 변경한 노드·선·계측만 화면에 전달한다. 선택한 본문은 지연 조회한다.

앞선 조사에서 확인한 `source.subagent`의 대소문자와 중첩 `CommandExecution`·`McpToolCall`의 실제 타입을 어댑터 계약에 반영해야 한다. 현재 세션의 네 과거 하위 세션을 읽을 수 있다는 사실만으로 이번 turn의 활동으로 연결하지 않는다. [실제 기록 조사](SESSION-WORK-TOPOLOGY-PLAN.md#3-우선-해결할-누락)

권장 관계 타입은 `belongsToTurn`, `calls`, `resultOf`, `spawnedSession`, `sentToSession`, `reportedBy`, `referencesArtifact`, `supportsClaim`, `observedUsage`, `recordedNext`, `dependsOn`이다. 시간순 `recordedNext`는 작업 의존성 `dependsOn`과 구분한다. 결과의 전달, 실제 소비, 공개 보고는 서로 다른 관계다.

각 관계에는 관찰한 출처 ID와 연결 근거를 둔다. 직접 ID 연결, 시작 이벤트 구간에 따른 연결, 의미 제안 연결을 구분한다. 소속을 특정할 수 없는 항목은 미확인 목록에 둔다. 임의로 가장 가까운 노드에 연결하지 않는다.

읽은 위치에는 파일 식별자·세대·byte offset·fingerprint를 보존한다. 부분 JSONL의 마지막 줄은 완결될 때까지 보류한다. 파일 교체·잘림·재개 시에는 출처 세대를 변경한다. 회로를 전환하거나 닫으면 기존 읽기를 취소하고 늦게 도착한 결과가 새 회로에 들어가지 않도록 범위와 generation을 확인한다.

## 9. 성능과 접근성

계측 갱신, 작업 상태 갱신과 전체 레이아웃을 분리한다. 로그가 추가될 때마다 전체 기록을 다시 읽거나 모든 노드를 재배치하지 않는다. 제안하는 갱신 방식은 짧은 구간의 이벤트를 합쳐 UI에 전달하고, 레이아웃은 구조가 바뀔 때만 계산하는 것이다. 갱신 주기는 실제 앱에서 측정한 후 결정한다.

회로 연결은 `Canvas` 또는 이에 준하는 렌더 계층으로 그리고, 선택·키보드·접근성은 stable ID를 가진 노드 계층으로 제공한다. 화면 밖 묶음과 닫힌 하위 회로는 신호를 그리지 않는다. 신호 애니메이션은 데이터 수집을 재실행하지 않는다. 백그라운드 창에서는 애니메이션을 중지한다.

선택과 확대 위치를 유지하며 새 이벤트의 위치는 표시로 안내한다. 사용자의 화면을 자동으로 이동시키지 않는다. 연결선은 다른 노드의 본문을 관통하지 않도록 배치한다. 혼잡할 때는 선택한 관계를 우선 강조하되 전체 관계의 구성원과 확인 범위를 유지한다.

모든 노드는 키보드로 선택할 수 있어야 한다. VoiceOver는 이름·종류·상태·소속 범위·관계·신선도를 읽는다. 색으로만 상태를 구분하지 않는다. `Reduce Motion`에서는 신호 움직임을 멈추고 동일한 상태 정보를 제공한다. 새 상태를 한 번 알리며 프레임마다 반복해서 읽지 않는다.
