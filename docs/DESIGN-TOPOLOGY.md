# 토폴로지 디자인 적용

기준 시안은 `design-previews/maestro-topology.html`이다. SwiftUI 구현은 시안의 색상, 카드 구조, 선택 동작, 연결선 구분을 적용한다. HTML 시안의 고정 크기를 그대로 복사하지 않고 기본 macOS 창의 중앙 영역에 맞게 카드 크기를 정했다.

## 적용한 동작과 표현

- 세션 카드는 240 × 112pt이며 프로젝트 카드는 240 × 58pt이다. 기본 열 간격은 285pt이다. 세 열을 85%로 표시하면 기본 중앙 영역에 들어간다.
- 프로젝트와 세션 카드는 중립 배경을 사용한다. 선택한 카드는 파란 테두리와 선택 배경을 사용한다. 사용자가 연결한 이웃 노드는 옅은 파란 테두리로 표시한다.
- 프로젝트 카드를 선택하면 프로젝트 상세를 표시한다. 프로젝트 카드 선택은 사이드바의 프로젝트 필터를 변경하지 않는다.
- 프로젝트 소속은 중립색 실선으로 표시한다. 사용자 연결은 프로젝트 → 프로젝트, 세션 → 세션, 프로젝트 → 세션, 세션 → 프로젝트를 모두 표시한다. 각 연결은 목적별 색상, 화살표, 목적 이름을 표시한다. 부모 세션 관계는 점선으로 표시한다.
- 프로젝트 카드의 연결 버튼과 컨텍스트 메뉴에서 프로젝트를 출발 노드로 지정할 수 있다. 세션 카드와 프로젝트 카드의 선택 동작은 노드 종류를 포함한 식별자로 도착 노드를 지정한다. 등록되지 않은 가상 프로젝트 그룹은 연결의 출발 또는 도착 노드로 사용할 수 없다.
- 연결 라벨은 모든 프로젝트·세션 카드와 먼저 배치한 라벨의 사각형을 피한다. 곡선 중간점 주변에서 최대 240pt까지 탐색한다. 카드 경계의 후보 위치도 검사하므로 45pt 열 간격보다 긴 라벨을 카드 위에 배치하지 않는다. 라벨과 카드 사이에는 2pt 간격을 둔다.
- 곡선에서 이동한 라벨에는 옅은 안내선을 표시한다. 탐색 범위에 빈 위치가 없으면 해당 라벨을 생략한다. 연결 화살표와 연결 상세는 유지한다.
- 캔버스 아래에 연결선 범례와 확대·축소·초기화·연결선 표시 버튼을 배치했다.
- 점 배경은 18pt 반복 이미지 타일이다. 밝은 테마와 어두운 테마의 타일을 각각 캐시한다. 드래그할 때 전체 크기의 배경 이미지를 생성하지 않는다.

## 보존한 경계

저장된 세션 위치는 기존 그래프 좌표로 유지한다. 새 기본 배치는 저장된 위치가 없는 세션에만 적용한다. 위치 초기화는 사용자가 초기화 버튼을 누를 때 수행한다.

드래그 이동은 해당 카드의 `GestureState`가 담당한다. 정적 연결선과 이동 중인 연결선의 렌더러를 분리한다. 이동 중인 카드와 연결선은 드래그 시작 위치를 유지한다. 제스처 취소 시 드래그 상태를 비운다. 기존 레이아웃 횟수 진단도 유지한다.

정적 라벨의 배치는 드래그 시작·종료 또는 그래프 입력 변경 시 계산한다. 포인터가 이동할 때는 해당 노드와 연결된 라벨만 다시 배치한다. 따라서 드래그 카드가 관계없는 정적 라벨을 가로지르면 그 라벨이 일시적으로 가려질 수 있다. 드롭 후에는 전체 카드 위치를 기준으로 라벨을 다시 배치한다.

사용자 연결의 투영은 `workspace.allNodeLinks`를 사용한다. 기존 세션 연결과 프로젝트 연결의 ID를 유지한다. 프로젝트와 세션이 같은 문자열 ID를 사용해도 서로 다른 노드로 구분한다. 세션을 드래그하면 해당 세션을 출발 또는 도착 노드로 사용하는 연결만 이동한다. 같은 문자열 ID의 프로젝트 연결은 이동하지 않는다.

같은 열의 연결은 노드 종류와 관계없이 카드 오른쪽 경계에 연결한다. 곡선의 제어점은 카드 밖에 둔다. 따라서 프로젝트에서 아래쪽 세션으로 연결할 때 중간 세션 카드의 본문을 가로지르지 않는다. 연결점의 세로 오프셋은 프로젝트 반높이 29pt와 세션 반높이 56pt를 기준으로 제한한다. 다른 열의 연결은 카드 좌우 경계에 연결한다. 현재 표시 범위에 없는 도착 또는 출발 노드는 그래프에서 임의로 다른 노드로 대체하지 않는다. 세션이 없는 프로젝트 행도 캔버스 높이에 포함한다.

## 검증

`swift test --filter 'TopologyDesignTests|PerformanceTests'`에서 7개 테스트가 통과했다. 실패는 0개다. 전체 로그는 `evidence/performance-design-tests.log`에 있다.

새 테스트는 양방향 연결의 이웃 노드 계산을 검증한다. 별도 테스트는 프로젝트 카드 선택 후 601개 세션의 표시 범위와 저장된 좌표를 유지하는지 검증한다. 기존 5개 테스트는 601개 세션의 그룹 구성, 정렬, 펼침·접힘, 드래그 상태의 Observation 분리를 검증한다.

이 로그는 소스 빌드와 자동 테스트의 근거다. 실제 macOS 화면의 배치, 연결선 라벨의 가독성, 밝은 테마와 어두운 테마의 시각적 결과는 별도의 런타임 관찰로 확인해야 한다. 자동 테스트 결과는 FPS 측정값이 아니다.

라벨 충돌 수정 후 `swift test --filter 'TopologyLabelPlacementTests|PerformanceTests|TopologyDesignTests'`를 실행했다. 최종 로그는 `evidence/performance-label-tests-final.log`이다. 새 기하 테스트는 45pt 간격의 같은 행 세션 연결, 58pt 프로젝트 카드 사이의 연결, 중간 세션 카드와 겹치는 연결, 역방향·병렬 연결의 라벨, 탐색 범위 밖 사각형의 침범, 빈 위치가 없는 경우를 검증한다.

혼합 연결 적용 후 `MixedTopologyTests` 5개와 기존 토폴로지·성능·라벨 테스트를 합쳐 18개 테스트가 통과했다. 실패는 0개다. 로그는 `evidence/performance-mixed-topology-tests.log`이다. 혼합 연결 테스트는 네 가지 노드 조합의 방향, 종류가 다른 동일 문자열 ID, 양방향 이웃 강조, 카드 경계, 드래그 중 혼합 연결의 이동, 표시 범위 밖 노드 생략을 검증한다.

스키마 버전 2 보호와 가상 프로젝트 연결 비활성화를 적용한 뒤 같은 18개 테스트와 `NodeLinkTests` 5개를 실행했다. 총 23개가 통과했으며 실패는 0개다. 최종 로그는 `evidence/performance-mixed-topology-tests-final.log`이다. 이 실행은 자동 테스트의 근거이며 실제 연결 관리 창, 캔버스 클릭, 드래그의 런타임 검증을 대체하지 않는다.

동일 열의 긴 혼합 연결 수정 후 토폴로지 관련 19개 테스트가 통과했다. 실패는 0개다. 로그는 `evidence/performance-mixed-route-tests.log`이다. 추가 테스트는 프로젝트 `(160, 68)`에서 세션 `(160, 456)`으로 가는 연결과 역방향 연결을 검증한다. 두 연결의 곡선은 중간 세션 `(160, 184)`, `(160, 320)`의 본문 밖에 있으며 기본 45pt 열 간격 안에 있다. 실제 macOS 화면의 화살표 방향과 라벨은 별도 런타임 관찰 대상이다.
